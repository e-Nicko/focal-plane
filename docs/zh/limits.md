# 它做不到什么

这个方法有意做得很窄。
以下是它的边界。

## 画面内

- **每个镜头一个页面**。
  每个镜头都是一张 canvas 放在一个平面上。
  镜头内的深度只来自相机与这个平面的夹角，
  没有悬浮在不同高度上的图层。
- **只用 canvas 2D**。
  画面里没有 DOM，也没有 CSS 布局。
  每个元素都以页面像素为单位手工摆放。
- **没有真正的 3D 物体**。
  玻璃、反射和挤出成型的形状属于相邻的类型：产品渲染。
- **刻意采用单色**。
  彩色也能用，但调色和这些文档都默认画面是灰色的。
- **没有音频**。

## 机器层面

- **需要带 GPU 的 Chrome**。
  工具通过 DevTools 协议驱动本机安装的 Google Chrome，
  用的是 `tools/cdp.ts` 中自带的一个小客户端
  （Playwright 在 Windows 上无法在 Bun 下运行）。
  播放器需要 WebGL 2，MP4 导出需要 WebCodecs，
  而 WebCodecs 只能在 `https://` 或 `localhost` 这类回环地址下运行。
  其他浏览器未经测试，
  除 Windows 11 之外的操作系统也未经测试。
- **在同一台机器上可重复，误差在 GPU 噪声之内**。
  时间、数据和相机都是精确的。
  在相同的 GPU 和驱动上把同一帧渲染两次，
  在我们的运行中最多有 0.0015% 的像素相差 8 位色的一级。
  换成其他 GPU，差别可能更大，出现在着色器运算的最后几位。
- **编码速度**。
  在 RTX 3060 Ti 上，4K60 母版渲染并编码的速度为每秒 16 到 20 帧，
  所以 16 秒的影片大约需要一分钟。
- **mp4-muxer 已被弃用**。
  它的作者现在维护的是 Mediabunny。
  mp4-muxer 仍然可用，
  迁移的改动只局限在 `src/engine/export.ts` 中。

## 技法层面

- **光标按脚本运动**。
  每个镜头各自写出光标路径；没有规划器。
- **字必须大**。
  4K 画面里的微距镜头只看到页面的三分之一；
  页面上小于约 13 px 的文字会变成纹理。
- **在小屏幕上，模糊会损失细节**。
  在手机上，清晰与虚化之间的差别变小，
  效果随之减弱。
