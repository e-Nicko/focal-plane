# 每一帧都是计算出来的

影片的每一帧都是时间的函数。
没有任何东西来自模型采样、屏幕录制或手工关键帧。

## 一帧就是 `f(t)`

- 镜头的 `state(t)` 是纯函数：同一个 `t` 总是给出同样的光标、焦点和数值。
- 相机关键帧用样条插值，从不做模拟。
- 数据用固定的种子一次性生成。
- 颗粒取决于帧序号；从不读取时钟。

因此，帧可以按任意顺序渲染，可以并行，也可以一次只渲染一帧。
浏览器内的播放器和离线渲染器运行同一份代码，
区别只在于它们请求哪些时刻。

## 这带来了什么

| | 生成的视频 | 计算的影片 |
|---|---|---|
| 第一帧 | 提示词发出后几秒 | 写几个小时的代码 |
| 文字 | 模型处理好的地方才清晰可读 | 4K 下处处锐利 |
| 数字 | 看起来说得通就行 | 彼此一致（[诚实的数据](honest-data.md)） |
| 一处修改 | 新的提示词，再掷一次骰子 | 改一个值，重新渲染 |
| 同一帧渲染两次 | 无法保证一致 | 一致，个别像素最多相差一级 |
| 审阅 | 看一遍 | 看一遍，做差异比对，读代码 |

## 生成模型已经学会了这个类型

视频模型熟悉这个类型。
Seedance 2.0 的提示词指南里就有它的模板：
一段 SaaS 应用预览，光标带着界面从空状态走到成功状态。
我们研究的那部参考样片很可能就是生成的：
在它的模糊区域里，文字糊成了一团。

生成模型很适合用来寻找氛围。
用它来展示产品就不合适了，
因为产品的文字和数字正是重点所在。

## 为什么适合交给智能体

这些页面里的语法足够明确，可以写下来，
所以也可以写成代码。
写镜头的智能体可以渲染一帧静帧，查看它，再修正相机，
这正是动态设计师在 After Effects 里反复做的循环。
[技能](../../skills/focal-plane/SKILL.md)把这个循环交给了智能体。
