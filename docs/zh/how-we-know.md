# 我们如何知道

这些页面中的每一条说法，要么经过测量，要么注明出处，要么标注为经验。
本页说明具体怎么做。

## 参考样片经过测量

起点是一部 8.4 秒的字体目录宣传片，
3840×2158，码率 7.7 Mbit/s。
它不在本仓库中：
它的版权归属不明，而且很可能是视频模型生成的。
我们对它做了逐帧测量：
切换落在哪里，每个镜头持续多久，
最暗和最亮的像素值，以及饱和度。
[画面](the-look.md)一页中的数字就来自这里。

## 名称都有出处

这个类型的词汇收集自素材网站、工具厂商和术语表。
在[来源](../sources.md)中，每个链接都带有一个标记：
🟢 表示已阅读原文，
🟡 表示仅见于搜索结果，
⚪ 表示来源给出的说法，我们无法核实。
像“约 3500 个模板”这样的数量，只是注明日期当天的搜索结果，
不能当作市场数据。

## 研究有引用，经验有标注

[为什么有效](why-it-works.md)一页把感知研究支持的内容与单纯的惯例区分开来，
并指出每项发现在什么地方不再适用。

## 每次渲染都要亲眼看

- 构图在静帧上完成：在几个时刻渲染静帧，看一看，调一个相机关键帧，重复。
- 联系表一次展示整个剪辑，用来检查节奏和连贯性。
- 检查 MP4 时，从文件本身解码出帧来看。
  只有亲眼看过解码后的帧，一次渲染才算完成。

## 改动都做差异比对

引擎迁入本仓库时，
我们对新旧代码渲染的静帧做了逐像素比对。
七个测试帧中有五个完全相同；
另外两个只在文字标志上有差别，那是有意改的名。
随后字体也迁入了仓库，
剩下的差别只有两个字形：≈ 和 σ，
它们此前由系统的回退字体绘制。
随后，离群值检测器不再被告知离群值埋在哪里（[诚实的数据](honest-data.md)），
主标签从 +4.0σ 变为 +3.8σ。

最后，代码从 JavaScript 迁到 TypeScript，工具从 Node 和 Playwright 迁到 Bun。
十个静帧中有九个与之前完全相同。
第十个是 1920×1080 的母版帧，在 2,073,600 个像素中有 41 个相差一级。
换成 Playwright 来驱动新代码，同样的差别依然出现，
所以问题不在浏览器驱动。
库文件与旧页面从 CDN 加载的那些逐字节相同。
我们没有找到原因。
同一条命令的重复运行，彼此之间的差别也差不多：
在 1280×720 的画面里，最多有 0.0015% 的像素相差一级。
我们把这当作 GPU 的噪声。

## 技能在一份新的需求上试过

一个手里只有这份技能的智能体，为一款虚构的恒温器应用做了一部两镜头影片。
其中一个镜头它用了五轮静帧，另一个用了三轮，
并指出技能和工具包里共有十个问题。
其中一个是真正的错误：
停在 19 上的数字，十位那一列被转动了 7%。
这个错误已经修复，技能里写错或缺失的地方也已改正。
影片本身不在仓库中。

## 速度经过测量

`bun run timings` 用单像素回读把管线的每个阶段隔开，
并打印 GPU 耗时（毫秒）。
[渲染管线](pipeline.md)一页中的数字就来自它，是在文中注明的硬件上测得的。

## 我们还不知道的

- 这些经验规则对设计和科技行业以外的观众是否成立。
- 在手机屏幕上，这种效果还能保留多少：那里的模糊在有些地方还不到一个像素。
- 参考样片的作者是全程使用了生成模型，还是只在部分地方使用。
